# Historical Map Tools

역사 지형도·식민지 지도·탐사 지도에서 공간정보를 복원하기 위한 QGIS 도구입니다. 한국 역사 도엽은 첫 검증 자료이지만, 기능은 특정 국가나 측지계에 고정되지 않습니다.

1. **Create Sheet Frame / 도곽 만들기**: 모든 QGIS CRS에서 네 모서리 도곽을 만들며, 경위도 DD/DMS와 투영 X/Y 입력을 모두 지원합니다.
2. **Register Map / 지도 맞추기**: 원본 스캔은 재표본화하지 않고 네 모서리와 선택적 내부 GCP로 프로젝티브 등록 JSON을 만듭니다.
3. **Extract Contours / 등고 추출하기**: 지도 프로파일의 색상 설정으로 가시 등고선을 추출하고, 등록 변환을 적용한 벡터와 검수용 연결 후보를 만듭니다.

Processing 도구상자에서 동일 기능을 일괄 처리할 수 있습니다. 가시 등고선과 연결 후보를 같은 GeoPackage에 저장하고, 후보 `status`를 `approved`로 고친 뒤 **Create Approved Contour Completions**을 실행하면 승인된 보완 구간만 별도로 출력합니다.

**Assess Contour Baseline / 등고선 기준선 측정**은 원본 스캔과 `MapProfile`을 받아 학습 없이 색상·형태학 처리 기준선의 가시선 수·길이·끝점·검수 후보 수를 JSON으로 남깁니다. 기본 분석 크기는 긴 변 2,048 px이고, 이 보고서는 정밀도·재현율이 아니라 프로파일 조정과 수동 정답선 제작을 위한 진단입니다.

각 도엽에는 원제·표시명·제작기관·조사 목적·시기·축척·언어/문자·CRS·스캔 출처·권리·역사적 맥락을 구조화하여 남깁니다. 원본 전체 스캔과 파생 결과는 Git에 넣지 않습니다.

고전 색상 기반 기준선과 Ink·합성 분류 실험을 함께 유지합니다. 첫 기준선 파일럿은 선명한 산지·지명 밀집·색바램/복잡 기호의 도엽 각 1장으로 `examples/korea_pilot_manifest.template.json`을 채워 반복 측정합니다. 원본 스캔은 Git에 넣지 않고 로컬 `data/raw/`에 두며, 실제 도엽의 ML 분할 도입은 기준선이 충분하지 않다는 측정 결과가 나온 뒤에 판단합니다. 표고 추론과 역사 DEM은 그 다음 단계입니다.

세 도엽 준비물, 실행 순서, 수동 정답선 평가, ML 도입 기준은 [초기 파일럿 프로토콜](docs/pilot-protocol.md)을 따릅니다.

현재 우선 작업은 [실제 도엽의 등고선 추출 개선](docs/contour-extraction-progress.md)입니다.
9개 개발 타일에서 벡터 변환의 가짜 분기와 미리보기 불일치를 수정하고,
문맥 필터 후보·원본 겹침 비교·새 QGIS 비교 프로젝트를 만들었습니다.
도로·하천 혼입은 아직 해결되지 않았으며 모든 출력은 검수 후보입니다.
후속 [주변 방향·간격 분류 실험](docs/contour-neighborhood-experiment.md)은 162개 고정 표본과
도엽 단위 검증으로 혼입 감소·추가 누락을 함께 확인했습니다. 선별·보수·불확실 후보와
54레이어 QGIS 비교 프로젝트를 제공하며, 새 모델은 기본 추출기를 대체하지 않습니다.
그 다음 [접촉 선 묶음·고정 새 표본 평가](docs/contour-forward-human-handoff.md)에서는
AI 임시 등고선 유지가 99/103에서 103/103으로 늘었지만 도로·기호 혼입은 남았습니다.
자동 개선 단계는 [90개 사례의 사람 판정·수정선 검수](docs/contour-human-review-guide.md)에
넘길 준비까지 완료했습니다. 사람의 수정 경로는 별도 학습 자료로 보존하며,
평가 전용 34개는 학습·임계값 선정에서 계속 제외합니다.

별도 보조 파일럿으로 [PaddleOCR 여백 판독 보조](docs/margin-ocr-pilot.md)를 준비했습니다.
명시적으로 선택한 모서리·도엽명·축척·범례 crop만 읽고 원문 이미지·OCR 원문·점수를
기록하는 독립 CLI입니다. Stanford 공개 원본 20도엽을 직접 확보해 실제 로컬 모델을
실행한 [기록과 한계](docs/margin-ocr-stanford20.md)를 제공합니다. 자동 좌표·CRS·GCP
적용은 없으며, 사람의 독립 전사에 따른 판독률 검증은 아직 수행하지 않았습니다.

스캔에 여백·범례·굵은 외곽 프레임이 있으면 이미지 자체의 네 모서리가 아니라 **인쇄된 지도 내부 도곽**을 `좌상 → 우상 → 우하 → 좌하` 순으로 클릭합니다. Processing에서는 같은 점을 `PIXEL_CORNERS`로 입력할 수 있습니다.

현재 실제 파일럿은 청양–공주 / 부여–논산 인접 흑백 도엽 4장입니다. 좌표 범위, `+10.4″` 보정 표기, 픽셀 GCP 및 흑백 추출 방향은 [4도엽 파일럿 문서](docs/korea-four-sheet-pilot.md)에 정리했습니다. 완전한 흑백 스캔이므로 기존 색상 분리 프로파일은 사용하지 않으며, 원해상도 타일 기반 흑백 선화 백엔드를 다음 구현 단계로 둡니다.

흑백 선화 비교 후보로 [Ink v2 중심선 A/B 워크플로](docs/ink-centerline-ab-workflow.md)를 추가했습니다. 이 결과는 등고선 판정이 아니라 문자·도로·하천을 포함할 수 있는 선화 중심선이므로 기존 검수 큐를 대체하지 않습니다. 기본 생성 명령은 개발 타일만 처리하며 공주 홀드아웃은 건드리지 않습니다.

옅어진 선, 글자·기호 가림, 긴 공백과 잘못된 평행선 연결은 [등고선 끊김 복원 연구](docs/contour-completion-research.md)의 합성 사례와 제한적 연결기에서 다룹니다. 안전 기본값은 사람이 `contour`로 검수한 선만 anchor로 사용합니다.

현재 우선 경로는 Ink 중심선을 약화시키지 않고 문맥으로 등고선 여부를
분류하는 것입니다. 개발 타일에서 고른 360개 선분 검토법, `Ctrl+4` 기호
라벨, 도엽 단위 교차검증 기준은 [Ink 선분 학습 워크플로](docs/ink-segment-learning-workflow.md)에 정리했습니다. 공주 도엽은 계속 최종 홀드아웃으로 제외합니다.

Ink 방향장·회피 영역·라벨 공백 연결과 합성자료 기반 등고선 점수화는
[Ink 발전·검증 워크플로](docs/ink-evolution-workflow.md)를 따릅니다. 실제
지도 점수는 검토용이며, 공주 도엽은 최종 평가 전까지 사용하지 않습니다.
