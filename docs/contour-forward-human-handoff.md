# 접촉 선 묶음·새 표본 평가와 사람 검수 인계

2026-09-12. [주변 방향·간격 실험](contour-neighborhood-experiment.md)의 후속입니다.
자동 작업은 새 평가와 실패 분석, 사람의 판정·수정선을 다시 읽는 경로까지 완료했습니다.
이제 필요한 것은 사람의 독립적인 선 의미 판정과 실제로 그을 경로입니다.
[검수 시작 안내](contour-human-review-guide.md)를 따르세요.

## 결과와 한계

기존 표본과 **선 ID가 겹치지 않는 새 162개**에서, 혼합·불명확 21개를 제외한
AI 임시 판독 141개를 평가했습니다. 사람 정답, 새 도엽 일반화, 전체 지도 정확도가 아닙니다.

| 새 고정 표본의 결과 | 기존 합성 모델 0.1 | 동결한 새 후보 |
| --- | ---: | ---: |
| 등고선 유지 / 103 | 99 | 103 |
| 비등고선 제외 / 38 | 5 | 8 |
| 도로·하천 제외 / 28 | 0 | 6 |
| 문자 제외 / 5 | 1 | 0 |
| 기호 제외 / 5 | 4 | 2 |

기존에 유지하던 등고선을 추가로 놓친 사례는 없었습니다. `E062, E108, E131, E142`를
회복했습니다. 도로·하천 `E020, E032, E036, E077, E144, E146`는 제외했지만
22/28개는 여전히 남았습니다. 문자 `E005`, 기호 `E012, E129`는 새로 혼입됐습니다.
미리 정한 임시 표본 기준은 충족했으나, **기본 추출기로 자동 승격하지 않았습니다**.
새 표본 결과를 본 뒤 모델·특징·임계값·AI 라벨을 다시 조정하지 않았습니다.

실제 9개 타일 출력은 전체 원래 선 8,736개, 기존 유지 7,940개, 새 유지 8,105개입니다.
두 유지 집합의 차이는 1,013개로, 기존에서 424개를 빼고 589개를 더했습니다.
이 개수는 정확도가 아닙니다. 모든 점수 레이어와 각 부분집합을 디스크에서 다시 읽어
원래 도형이 그대로임을 검증했습니다. 새 선·공백 연결·표고·사람 승인은 생성하지 않았습니다.

## 무엇을 시험했나

기존 선이 정확히 같은 픽셀 끝점에서 맞닿은 경우에만 문맥용 묶음을 만듭니다.
끝점 차수가 2 또는 3이고, 8픽셀 구간 접선의 진행 방향 변화가 20° 이하이며,
대안과의 각도 차이가 25° 이상인 경우를 사용합니다. 네 갈래 교차·애매한 분기·
떨어진 끝점은 연결하지 않습니다. 내부 특징 계산용 묶음이지, 출력 도형 병합이 아닙니다.

8,736개 중 654개(약 7.5%)만 다중 선 묶음에 포함됐습니다. 이전 누락 사례
`S055, S058, S077, S086, S090`는 모두 고립 선이었습니다. 길이 필터 전의 청양
원시 선망에서도 이 문제를 단순 접촉 연결로 해소할 수 없었습니다.
따라서 “선 묶음만 추가하면 희미한 선이 복원된다”는 결론을 내리지 않습니다.

다섯 특징 집합 × 내부 등고선 유지 목표 95%·100%, 총 10개 개발 시험을 보존했습니다.
선 묶음 특징은 고립 선에서 정확히 0인 차이값으로 만들어, 같은 특징을 중복 입력하면서
정규화 효과만 바뀌는 비교를 피했습니다. 선택된 `legacy_prior_chain-inner1`은
기존 모델 log-odds 1개(±6 제한), 주변 특징 23개, 묶음 차이 특징 20개, 총 44개입니다.
L2=0.1을 고정한 작은 로지스틱 모델이며 새 외부 모델을 내려받지 않았습니다.

아래는 **방법 선택에 사용한 이전 S 표본**의 개발 결과입니다. 새 정확도 평가가 아닙니다.

| 특징 집합 | 내부 유지 목표 | 등고선 유지 / 106 | 비등고선 제외 / 42 |
| --- | ---: | ---: | ---: |
| 주변 문맥 | 95% | 101 | 25 |
| 주변 문맥 | 100% | 104 | 14 |
| 선 묶음 형태 | 95% | 100 | 24 |
| 선 묶음 형태 | 100% | 106 | 10 |
| 선 묶음 문맥 | 95% | 102 | 23 |
| 선 묶음 문맥 | 100% | 104 | 13 |
| 기존 점수 + 주변 문맥 | 95% | 103 | 26 |
| 기존 점수 + 주변 문맥 | 100% | 103 | 18 |
| 기존 점수 + 선 묶음 | 95% | 102 | 26 |
| 기존 점수 + 선 묶음 | 100% | 106 | 15 |

기존은 104/106 유지·13/42 제외였습니다. 기존이 유지하던 등고선 **ID의 추가 누락이
없으면서** 비등고선을 더 제외하는 방법 중 제외 수, 등고선 유지 수, 적은 특징 수 순으로
골랐습니다. 단순히 총 유지 수가 같다는 이유로 추가 누락을 허용하지 않습니다.
접촉 묶음 특징 단독의 우월성이나 인과 효과는 이 작은 탐색 결과로 입증되지 않았습니다.

## 평가를 분리한 방법

1. 동일한 9개 개발 타일의 원래 선망에서 seed `20260913`, 세 길이 구간별 타일당
   6개를 뽑았습니다. 이전 S162의 모든 선 UID를 제외했습니다.
2. 개발 명령은 이전 S 라벨만 받습니다. 새 E manifest는 중복 검사·동결용으로만 읽고,
   새 라벨 입력 인자는 없습니다. 위 10개 비교도 이전 S 자료에서만 수행했습니다.
3. 선택한 방법, 세 도엽 제외 모델의 계수·임계값·학습 ID, 입력·구현 해시를
   [프로토콜](../examples/contour_forward_protocol.v1.json)에 먼저 동결했습니다.
4. 새 모델 예측을 보기 전에 원본·대상 선 화면 27쪽에서 E162 전체의
   [AI 임시 라벨](../examples/contour_forward_labels.ai-v1.json)을 고정했습니다.
   등고선 103, 도로·하천 28, 문자 5, 기호 5, 불명확 18, 혼합 3개입니다.
5. 평가 명령은 동결 모델로 점수화만 하며 학습하지 않습니다. 각 도엽의 출력에는
   다른 두 도엽으로만 학습한 모델을 씁니다. 평균·표준편차와 임계값도 평가 도엽에서
   추정하지 않습니다. 구현·입력 해시가 다르면 재현 실행을 중단합니다.

선 ID는 새 것이지만, 부여·청양·논산이라는 **같은 도엽·타일·주변 영상 문맥**을 공유합니다.
모델 계열 선택도 이전의 같은 세 도엽에서 했습니다. 공간적으로 독립인 최종 시험이 아닙니다.
길이 구간별 균등 표집이며 AI 판독 오류도 가능하므로 모집단 정밀도·재현율을 주장하지 않습니다.
처음부터 Ink 후보가 없었던 희미한 선, 잘못된 기존 합류, 완전한 지도 연결성은 이 평가 밖입니다.
공주 최종 홀드아웃과 기존 사람 검수 GeoPackage는 계속 건드리지 않았습니다.

로컬 공통 경로는 `data/derived/contour-chain-2026-09-12/`입니다.

- `forward-evaluation-final/forward_evaluation.json`: 새 162개 점수·판정과 9개 타일 출력 해시.
- `forward-comparison-final/report.html`: 162개 개별 표본과 9개 전체 타일의 원본·기존·새 출력.
  `forward-examples.png`의 E062·E020·E005는 결과를 본 후 고른 설명용 성공·실패 사례입니다.
- `development-frozen/development.json`: 이전 S 자료의 10개 개발 실험 전체.
- `human-review-ready/`: 원본 입력 타일·읽기 전용 대상 선·90개 북마크를 포함한 새 QGIS 검수 묶음.
  처음에는 전부 미검수이고 이름·승인·사람 수정선이 비어 있습니다.
- `human-feedback-ready/`, `human-training-ready/`: 실제 파일을 읽어
  사람 승인 0, 학습 라벨 0, 모델 학습 안 함을 확인한 기록.
- [증거 JSON](evidence/contour-forward-2026-09-12.json): 프로토콜·입력·출력·검수 파일 해시,
  10개 개발 결과와 새 162개 평가 기록. 대용량 지도·검수 GeoPackage는 Git에 넣지 않습니다.

비-QGIS 테스트 167개, 로컬 QGIS 3.44.8 통합 테스트 8개를 통과했습니다.
새 QGIS 파일은 저장 후 다시 열어 13개 유효 레이어와 90개 북마크를 확인했습니다.
상대 경로로 생성한 뒤 별도 위치로 옮긴 사본도 열어 모든 레이어의 이동 후 출처를 확인했습니다.
테스트에서 사용한 사람 승인·수정선은 임시 합성 fixture이며 실제 검수 파일에 넣지 않았습니다.
전체 비교 HTML의 이미지 참조와 원본 도형 보존을 확인하고, 대표 타일·사례·QGIS 렌더를
눈으로 검토했습니다. 이번 9개 타일 점수화·출력은 약 9.3초였고 정식 성능 벤치마크는 아닙니다.

프로토콜 사본의 부동소수점 JSON 재직렬화로 바이트 해시가 달라지는 출력 버그는,
원래 프로토콜을 그대로 복사하도록 수정했습니다. 최종 폴더에 다시 실행한 결과는
이전 실행과 같은 판정·개수였으며, 모델이나 평가 라벨을 바꾸지 않았습니다.

## 고정된 평가 재실행

기존 개발 타일, corner-safe raw vector index, S/E manifest가 로컬에 필요합니다.
Python 3.12와 NumPy·SciPy·Pillow 환경에서 실행하고 항상 새 출력 폴더를 사용합니다.
동결 평가를 반복하려면 개발 방법 선택을 다시 돌리지 않고 저장된 프로토콜을 씁니다.

```sh
python scripts/evaluate_contour_forward.py \
  data/derived/annotation_package/index.json \
  --vectors data/derived/contour-extraction-2026-09-12/corner-safe-final/ink_candidate_vector_index.json \
  --training-samples data/derived/contour-context-2026-09-12/semantic-samples/manifest.json \
  --forward-samples data/derived/contour-chain-2026-09-12/forward-samples/manifest.json \
  --forward-labels examples/contour_forward_labels.ai-v1.json \
  --protocol examples/contour_forward_protocol.v1.json \
  --legacy-model examples/ink_synthetic_legacy_model.json \
  --output data/derived/contour-forward-next/evaluation
```

소스 바이트 해시까지 확인하므로 체크아웃의 줄바꿈도 동결 당시 LF여야 합니다.
다른 입력·구현에는 프로토콜 해시를 임의로 고쳐 재사용하지 말고 새 연구 버전을 만듭니다.
사람 검수와 그 이후의 학습 명령은 [별도 안내](contour-human-review-guide.md)에 있습니다.
