# 원본 기반 등고선 재구성 — 진행 중

2026-09-14. 목표는 **숫자·문자 혼입을 줄이고, 흐린 등고선을 원본에서 연속적이고
자연스럽게 추적하는 기능 강화**다. 호환성 수정, 테스트 통과, 검수 자료 생성만으로
이 목표가 달성된 것은 아니다. 현 단계는 기본 추출기를 대체하지 않는 개발 실험이다.

## 완료 기준과 아직 남은 범위

1. QGIS Qt5/Qt6 입력·미리보기·취소·저장 호환성을 회귀 검사한다.
2. 원본에서 고른 24개 개발 영역(숫자, 문자 겹침, 흐린 선, 곡부, 밀집 평행선,
   하천·기호 각 4개)을 고정한다. `examples/contour_reconstruction_regions.v1.json`.
   유형은 AI의 장면 설명이며 사람 정답이 아니다. 최종 시험 표본도 아니다.
3. 문자 검출 영역 안에서 실제 문자 획과 통과하는 선을 구분한다. 검출 박스 전체를
   지우지 않는다. OCR 내용·검출 점수·픽셀 소유권은 서로 다른 근거다.
4. 기존 벡터의 연결에 한정하지 않고 원본의 약한 잉크를 추적한다. 처음부터 누락된
   선과 짧은 조각을 보존하고, 연속 방향·주변 간격을 이용한다.
5. 숫자 공백에서는 주변 여러 끝점의 순서·일회 사용·비교차 제약으로 연결을 제안한다.
   이 단계의 흰 공백은 관측 잉크와 다른 **추정 연결**로 남긴다.
6. 경로가 정해진 뒤 픽셀 잔굴곡을 정리한다. 원본 중심·진짜 곡부·이웃 선 간격을
   검사하고 기존 승인 좌표는 정확히 잠근다.
7. 한 번에 2–3건씩 사람에게 의미/연결 상대/형상을 각각 물어본다. 승인되지 않은
   후보, 물음표, 추정 경로, 표시하지 않은 픽셀은 학습 정답으로 승격하지 않는다.
8. 별도 공간/도엽 검증에서 문자 잔존 길이, 관측 등고선 보존·회복, 잘못된 연결과
   곡부 훼손, 승인 좌표 보존을 평가한 뒤 통합한다. 공주 홀드아웃과 기존 S/E 자료는
   지금 조정·학습에 쓰지 않는다. 최종 지도/GIS 산출물과 실제 QGIS4.2 CI 검증이 남는다.

## 현재 구현

- `map_text_detection.py`: 기존 로컬 고정 모델로 지도 내부 검출 다각형과 검출 점수를
  보존한다. 인식 문자열/인식 점수는 별도 기록. 원본 9개 개발 타일에서 288개 영역을
  검출했지만, **505와 기울어진100/200을 놓친 사례**를 확인했다. 영역 개수는 정확도가 아니다.
- `text_ownership.py`: 원본 잉크 픽셀 안에서 고립된 진한 비선형 성분에만 soft 회피
  근거를 부여한다. 단일 고리·직선·연결 접점·불확실 성분은 별도로 보존한다. 288개
  영역 탐색에서 soft 1,298px, ambiguous 227,603px, throughgoing 566px였다. 대부분을
  보류하므로 숫자 제거가 해결된 상태가 아니다.
- `observed_linework.py`: 연속 Ink 지지도와 법선 명암 대비로 약한 관측 획을 보존하고,
  강한 시작점에서 방향이 이어지는 획을 확장한다. 원래18px 길이 필터와 정점512개
  제한을 적용하지 않고 짧은 원시 그래프 간선도 문맥으로 남긴다. 긴 약한 성분은 별도
  근거로 유지한다. 의미 분류, 흰 공백 연결, 전역 위상 복원은 이 모듈의 성과가 아니다.
  Ink `coherence`가 순수 방향 일관성이 아니라 잉크 지지도와 곱해진 값임을 확인했다.
  이를 그대로0.3과 비교하면 정확히 평행한 약한 선도 탈락하므로 분리한 회귀시험을 추가했다.
- `directional_trace.py`: (위치, 진입 방향) 상태로 명시한 양끝 사이를 탐색한다. 무지원
  구간을 bilinear 지지도의 실제 임계 교차로 측정하여, 작은 공백도 관측 잉크로 숨기지
  않는다. 실제 탐색 3곳 중 곡부 1곳은 중간 근거 부족으로 기권했다. 이는 성공률 평가가 아니다.
- `observed_curve.py`: 단일 잉크 봉우리의 중심을 따라 구간별 곡선을 적합한다. 경계의
  잘린 획으로 인한 예외와 오판을 회귀시험으로 재현·수정했다. 실제 후보 일부에서
  총회전량이 증가했으므로 원본 지지율만으로 매끄러움 개선을 주장하지 않는다.
- `reconstruct_observed_contours.py`: 위 관측 추출/획 근거/곡선 적합을 새 실험 출력에
  연결한다. 선택 영역 밖의 원래 구간을 잠그고, 총회전량 증가나 영역 밖 이동은 초안
  채택에서 제외한다. 승인선은 바이트 동일한 별도 레이어로 복사하며 기존 망에 적용하지 않는다.

- `observed-v1/`, `observed-review-v1/`: 첫 2개 타일/3개 구역의 탐색 초안. 이후 검토에서
  선택 영역 판정이 bounding box만 사용하고 영역 밖 경로까지 적합하는 문제가 발견되었다.

  약한 성분 보존이 방향 거절을 우회하고 대각선 길이를 정점 수로 세는 문제를 확인했다.
- `observed-v3/`: 위 두 문제를 회귀시험으로 재현·수정했다. 방향 거절을 우회하지 않고
  **강한 시작점이 없는 고립 성분만** 실제 픽셀 길이로 추가 보존한다. 출력 도형 길이도
  다시 계산하고 원시 잉크 지지도와 명확히 구분한다. 235개 곡선 적합 중177개를 실험
  초안으로 채택했다. 이것도 사람 승인율이 아니다.
- `human-review-001/`: v3의 정확한 두 조각 N001/N002를 고정한 검수 비교판/도형/해시.
  새로운 공백 연결이 아니라 **관측 조각의 등고선 여부와 형상**만 묻는다. 기존 A 사례와
  다른 식별자이며 학습용이 아니다. 2026-09-14에 두 질문을 제출했으며 아직 답변은 없다.
- `text-multiscale-v2/`: R004/R015/R009 2배·4배의 고정 로컬 OCR 비교. 13개 영역이
  검출됐으나 505는2배에서50으로 잘렸고4배에서누락, 100/200은미해결이었다.
  단순 확대를 개선안으로 승격하지 않고 connected-component 문자군 검색을 다음 실험으로 삼는다.
- `component-text-recognition-v2/`: 성분 묶음의 기울어진 사각형을 검출기 없이 직접
  인식했다. 276개 후보·476개 인식 결과·76개 경계 초과 보류를 모두 보존한다.
  R004의 rank21에서 두 배율 모두 **505**, R015의 rank12에서 두 배율 모두 **100**을
  읽었다. 200 전체는 읽지 못했다. 같은505를 읽은 rank3에는 이웃 곡선도 들어 있어,
  문자열 인식이 맞아도 후보 성분 전체를 문자 획으로 확정할 수 없음을 확인했다.
  기존 OCR 환경에는 SciPy가 없어 설치 대신 이미 있는 수치 계산 Python과 인식 Python을
  데이터 전용 worker로 분리했다. 원본·모델·양쪽 런타임·구현의 전후 검증을 수행했다.

첫 초안에서는 241개 적합 시도 중204개를 총회전량 비증가 조건으로 채택했다. 이 수치는

## 재현 예시

아직 존재하지 않는 출력 폴더를 사용한다. 기존 로컬 원본/검수 스냅샷이 필요하다.

```sh
python scripts/reconstruct_observed_contours.py \
  data/derived/contour-assisted-2026-09-13/human-review-final \
  examples/contour_reconstruction_regions.v1.json \
  data/derived/contour-reconstruction-2026-09-14/text-detection-v1/text-detection.json \
  data/derived/contour-vectorized-2026-09-14/v1-portable/approved-connections.geojson \
  --regions R004 R009 R015 --output data/derived/contour-reconstruction-replay
```

코드/합성 시험과 실제 지도 품질 검증은 별개다. 이 체크포인트에서는 비-QGIS **400개**,
로컬 QGIS3.44.8 통합 **15개**가 통과했다. 실제 v3 GeoJSON 5개 레이어를 QGIS에서 열어
EPSG:5132·도형 유효성·저장된 모든 정점의 좌표 동일성을 확인했다. 원본 crop24개의 픽셀,
보호 입력14개 해시, 승인선23개 파일의 바이트 보존, ZIP56개 항목과 소스의 바이트 일치도
확인했다. 실제 QGIS4.2 CI 재검증과 전체 성능 검증은 남아 있다.

검증 범위·보고서/산출물 해시·남은 요구사항은
[중간 증거 기록](evidence/contour-reconstruction-2026-09-14.json)에 남겼다. 기본 추출기 교체,
기존 망 변경, 학습, 새 승인, 표고 할당은 수행하지 않았다. 이번 변경은 아직 커밋·푸시하지 않았다.

## 추가 체크포인트: 24개 구역의 숫자 획 분리

`component-text-recognition-all24-v1`의 고정 인식 결과를 사용하여
`numeric-separation-all24-v2`를 생성했다. 원본 이미지나 기존 지도는 지우지 않고,
새 관측선 초안을 보존용 전체 조각·유지 후보·숫자 후보 레이어로 분할한다.
원래 42,775개 선 중 27개를 분할했으며 전체 조각 42,793개 중 숫자 후보는 36개다.
이 개수는 정확도나 사람 승인 수가 아니다.

R002의 `152`는 문자열 충돌이 아니라 전체 문자열의 위치 후보가 하나뿐이라
보류됐었다. 이제 `15`·`52` 같은 부분 문자열이 동일한 연결 성분을 같은 순서로
가리키고, 모든 자리의 성분에 중첩 근거가 있을 때만 보조 근거로 쓴다.
이 경로는 한 자리당 한 성분 대응이 가능한 제한적 가설이며, 붙은 글자나 분절된
글자의 일반적인 성분 수를 문자 수로 간주하지 않는다. 부분 성분 탐색은 근거에서
제외하고 기존 경계 보호·문자열 충돌 보류·높이/간격 검사는 유지한다.

R002는 숫자 후보 0→200픽셀, R001은 0→229픽셀이며 비교판에서 숫자 몸체와
대응하는 것을 개발자가 시각 점검했다. R004의505(255픽셀), R015의100(204픽셀)은
유지됐다. R001의 소수점/마지막 자리, R003·R005의 미분리 부분, 선에 붙은200은
해결되지 않았다. 숫자값을 표고로 할당하지 않았고 N001/N002도 여전히 미승인이다.

추가 회귀시험을 포함한 비-QGIS 시험 **457개**가 통과했다. 이는 코드 계약 검증이며
독립 지도 정확도 평가가 아니다. 숫자 분리·선 분할·영역 매칭 시험을 CI 목록에
추가했다. 원본 보존과 선 연결/평활화 통합을 계속 검증해야 하며 기본 추출기는
교체하지 않았다. 이전 400개 시험/ZIP 체크포인트는 당시의 기록으로 유지한다.

후속 실파일 QGIS 검사에서 v2의 유지 조각 3개가 원래 좌표계의 부동소수점 정밀도에서
길이 0으로 겹치는 것을 발견했다. 해당 부모 선은 통째로 유지하며 분할 보류 이유를
기록하는 방어 로직과 회귀시험을 추가했다. 최신 출력은 `numeric-separation-all24-v3`이며
24개 부모 선을 분할해 유지 42,756개·숫자 후보29개·전체42,785개를 보존한다.
따라서 위 v2 수치를 최신 최종 출력 수치로 사용하면 안 된다. ZIP도 최신 코드로 재생성했다.
최신 비-QGIS458개·로컬 QGIS15개 시험이 통과했다. v3의 네 출력 레이어를 실제 QGIS에서
열어 모든 도형의 유효성, EPSG:5132, 저장된 정점과 읽은 정점의 정확한 일치를 확인했다.
입력 초안과 승인선23개의 출력 사본도 원래 파일과 바이트가 동일했다.

## 추가 체크포인트: 붙은 숫자 검색 범위의 잘림

내부 구멍 축을 이용한 검색 띠의 법선 방향 경계에 잉크가 닿으면, 중앙 구멍 높이의
절반만큼 해당 방향을 넓힌 대안 하나를 생성한다. 기존 검색 사각형은 유지하며,
대안도 작업량/출력 개수 상한에 포함한다. 확장 사각형은 숫자 소유권이 아니며
붙은 등고선을 포함할 수 있음을 기록한다. 단일 성분 검색은 명시적인 부분 검색일
때에만 인식기에 전달할 수 있도록 허용/거절 회귀시험도 추가했다.

`component-text-recognition-v4`에서 R004/R009/R015를 같은 고정 모델로 2배·4배
재검사했다. R015 성분198의 기존 띠는 첫 자리 하단의 점검 대상6픽셀을 모두
제외했으나 확장 띠는6개 모두 포함했다(성분 내부 포함232→247픽셀).
그럼에도 인식값은 두 배율 모두 `800`(.788/.794)이다. 시각적으로 추정한 `200`의
인식 성공으로 보고하지 않는다. 원본 연결 성분/픽셀 배열과 공통 후보 사각형·문자열은
이전 v3와 같으며, R015의 기존 최하위 후보 하나는 출력 상한으로 밀려나 누락 기록에 남는다.

후속 `numeric-separation-recognition-v4`에서505의255픽셀과100의204픽셀은 유지됐다.
새 단일 성분 읽기는 전체 성분의 숫자 소유권을 부여하지 않아 붙은 선을 제거하지 않는다.
3구역 재검사일 뿐 전체24구역 독립 성능 평가가 아니며, 실제 글자값 인식과 문자/선이
붙은 접점의 구분은 미해결이다. 최신 비-QGIS461개 시험이 통과했고 ZIP을 재생성했다.

## 추가 체크포인트: 실제 끝점과 영역 순서 매칭 연결

`gap_endpoint_context.py`와 `inspect_numeric_gap_context.py`로 기존 순서 매칭기를
원본 래스터 관측 경로에 연결했다. 평활화/분할 후 끝점이 아닌 인접 정수 픽셀 경로만
입력받고, 실제 연결 차수가1인 끝점만 사용한다. 다른 경로의 중간에 닿는 끝점도
분기점으로 제외한다. 이미지 경계·숫자 검색 상자 내부·6픽셀 방향 꼬리가 부족한
끝점은 제외하며, 끝점의 진행 방향이 검색 상자로 들어오는지도 검사한다.

`numeric-gap-context-v2`는 전체24구역 숫자 분리 결과 중 숫자 획 후보가 있는
R001/R002/R004/R015/R017 다섯 곳의 검색 문맥을 사용한다. 각 문맥에서 네 방향의
끝점 배열과 최선/차선 순서 매칭을 보존했다. 다른 관측 획과 교차하는 직선 연결은
추가로 보류한다. 방향별 대안 사이의 전역 선택은 수행하지 않아 모든 경우에
`eligible_for_automatic_connection=false`이며 실제 연결 적용은0개다.

실제 비교판에서는 방향 가정에 따라 상당히 다른 선이 연결된다. 따라서 순서와
끝점 방향 검사만으로 지도 연결 품질이 확보됐다고 볼 수 없다. 주변 등고선의
연속적인 진행 방향, 큰 문자 생략 영역의 경계, 문자와 연결된 선의 접점 추론이
다음 통합 요구사항이다. 빨간 선은 매칭 진단용 직선이지 채택된 등고선이 아니다.
원본 이미지/관측 경로/숫자 분리 스냅샷을 변경하지 않고 별도 PNG와 JSON을 생성한다.
이 단계의 비-QGIS469개 시험이 통과했으며 실행 전후 입력/구현 파일 해시 일치가
보고서 생성 전에 검증됐다. 기본 추출기 교체, 사람 승인, 커밋·푸시는 수행하지 않았다.

## 추가 체크포인트: 주변 관측선 방향을 이용한 후보 평가

`contextual_gap_ranking.py`는 방향별 최선/차선 후보를 끝점 쌍 기준으로 중복 제거하고,
연결하려는 두 부모 경로 및 숫자 상자 내부를 제외한 주변 경로로 방향 텐서를 계산한다.
각 경로는 표본 위치마다 한 번만 투표하며 최대8개 경로를 사용한다. 세 표본 위치 중
두 곳 이상에서 최소3개 경로·축 일치도0.65 이상의 근거가 있을 때만 방향 벌점을
계산한다. 이는 등고선 의미 판별이 아니며 도로 등도 방향 근거에 섞일 수 있다.

실제 5개 문맥 재실행에서 숫자 상자 밖의 평행한 연결이 상위에 오르는 문제가 드러나,
직선 후보가 숫자 검색 문맥을 최소1픽셀 통과하지 않으면 순위 비용을 부여하지 않도록
수정했다. 최신 증거는 `numeric-gap-context-v4/gap-context-report.json`이다.
근거 부족을 비용0으로 취급하지 않고 null로 남기며, 끝점 재사용과 후보 간 교차를
충돌 목록으로 기록한다. 방향별 중복 제안은 독립 근거 수로 늘리지 않는다.

주변 방향 평가를 적용해도 숫자의 실제 생략 범위·곡선 경로·문자/선 접점은 아직
확정되지 않았다. 순위는 검수 보조 자료이고 전역 망 선택/연결 적용은0개다.
원래 방향별 빨간 직선 비교판은 그대로 진단 후보를 보여 주며 순위 채택 결과가 아니다.
중복 제거된31개 끝점 쌍 중13개에만 문맥 순위 비용이 부여됐고, R015는 전부 보류됐다.
비-QGIS478개 시험이 통과했으며 ZIP을 재생성했다. 이 수치는 연결 정확도가 아니다.

## 추가 체크포인트: 문맥 후보의 곡선 초안

`context_gap_preview.py`가 기존 `manual_gap_bridge`와 짧은 연결 보정기를 재사용해
문맥 순위가 있는 후보의 곡선 초안을 만든다. 원래 끝점을 고정하고 부모 꼬리는
수정하지 않는다. 수동 도구의 축 반전 허용을 자동 후보에 그대로 사용하지 않도록
바깥쪽 접선의 부호부터 확인한다. 곡률 제한으로 원래 접선과 달라진 경우에는
표본 접선 오차를 보고하며12도 초과를 통과로 처리하지 않는다.

`numeric-gap-context-v5`에서 점수가 있는13개 후보 중12개가 곡선으로 생성됐다.
모든 곡선 구간을 원래 관측 경로와 다시 교차 검사했으며11개는 교차 또는 접선
불일치로 보류됐다. R004의 `context-gap-002`만 기하 검사를 통과했다.
이것도 등고선 의미/연결 정답을 증명하지 않으므로 미승인으로 유지한다.
R004의505 가운데를 지나는 이 초록색 연결에 대해 연결 대상과 곡률을 구분한
사람 판정을 요청했다. 다른 R영역의 동일한 지역 후보 ID와 혼동하지 않아야 한다.
정확한 식별자는 `R004-numeric-hypothesis-2c065993a8211a55/context-gap-002`이며
점 좌표와 비교 PNG 경로는 v5 보고서의 `curve_previews`에 고정돼 있다.

비-QGIS484개 시험이 통과했다. 원래 지도/승인선 수정과 자동 연결 적용은 수행하지
않았다. 경로 간 곡선 충돌 목록도 남겼으며 개별 기하 검사 통과를 전역 망 승인으로
승격하지 않는다. QGIS 출력 통합과 전체 의미/연결 품질 검증은 여전히 남아 있다.

## 사람 피드백: R004 연결 승인, 직선 허용

사용자: “잇는건 매우 잘했는데 그냥 직선으로 이어도 무방할듯.”
바로 앞에 제시한 R004/context-gap-002에 대한 연결 승인과 직선 허용으로 기록했다.
별도 등고선 의미 판정을 새로 만들어내거나 전역 직선화 정책으로 확대하지 않았다.
`examples/contour_gap_feedback.v1.json`은 원래 v5 보고서 SHA256·부모 경로 ID·정확한
끝점을 고정한다. `apply_context_gap_feedback.py`는 이 식별자가 모두 일치할 때만
별도 직선 수정본을 생성한다. 원래 곡선/지도/기존 승인 기록은 수정하지 않는다.

`connection-feedback-001`의 직선 끝점은(676,289)→(674,312)이며, 비교 PNG와
EPSG:5132 GeoJSON, 사용자 발언 및 적용 기록을 보존했다. 승인 범위는 이 연결뿐이며
학습·전체 선망 승인·표고 할당은 없다. 보고서/끝점 불일치 거절과 의미 승인 분리의
회귀시험을 추가했다. QGIS 통합 작업에 이 국소 수정본도 별도 레이어로 포함할 예정이다.

## 흐린 구역의 짧은 끊김 재추적

기존 벡터화기는 이미 `corner_safe` 대각선 정책으로 픽셀 모서리의 중복 분기를
억제하고 있었다. 따라서 분기를 추가로 삭제하지 않고 `short_ink_recovery.py`로
실제 끝점 사이2–12픽셀 끊김의 잉크 재추적을 연결했다. 같은 부모 경로끼리의 연결,
서로 반대인 접선, 비슷한 거리의 경쟁 끝점은 제외한다. 기존 방향 상태 추적기의
지지율0.08·허용 비지지 연속 길이2픽셀 기준은 사례별로 낮추지 않았다.

`recover_short_observed_gaps.py`를 고정 흐린 구역 R009–R012에 적용한
`short-ink-recovery-v1`에는 후보78개가 남았다. 실제 잉크 지지 재추적1개(R012),
관측 지지 부족24개, 경로 없음51개, 경쟁 끝점 보류2개다. 재추적1개도 등고선
의미나 전역 연결 정답이 아니고 아직 원래 경로에 병합하지 않았다.
흰 공백을 실제 잉크로 둔갑시키지 않고 비지지 구간을 따로 기록한다.

이 결과는 광범위한 흐린 선 복원을 달성한 증거가 아니다. 최초 관측 추출의 약한
지지 기준0.025와 재추적 기본 기준0.08의 차이, 실제 원본의 공백과 저대비 잉크를
분리하여 다음에 검토해야 한다. 숫자 큰 생략 구간은 이 짧은 잉크 복원기의 범위가
아니며 별도 추론 문제로 유지한다. 비-QGIS489개 시험이 통과했다.

## 흐린 잉크 기준 차이의 통제 비교

`short-ink-recovery-v2`에서 동일한78개 끝점 쌍을 기존0.08 기준과
원본 법선 명암 차이0.008로 보호한0.025 기준으로 비교했다. 모든 후보에 같은
기준을 사용하며 기존 결과를 덮어쓰지 않는다. 명암 보호는 초기 관측 추출과 같은
0.55 가우시안/양쪽2픽셀 프로파일을 사용하고 원래 지지율만0으로 차단한다.
새로운 픽셀이나 포화된 중심선 점수를 잉크 근거로 추가하지 않는다.

기존 재추적1개는 그대로 재현됐다. 낮은 기준의 민감도 결과는 실제 지지 경로9개,
짧은 비지지 구간 포함2개, 보류67개다. R009는4+1개, R010은0개,
R011은1개, R012는4+1개다. 원본 겹침을 점검했으며 일부 흐린 선 사이의
끊김이 복원됐지만 도로/하천 등 의미 혼입 가능성은 남는다. 이 수치를 등고선
정확도나 사람 승인 수로 보고하지 않는다.

평탄한 종이에 잘못된 높은 지지 점수가 있어도 차단되는 시험과 저대비 원본 획의
통제 재추적 시험을 추가했다. 비-QGIS491개 시험이 통과했다. 일반 추적기의 기본
기준은 바꾸지 않았으며 새 분기는 명시적인 민감도 비교로 보존한다. 지지 기준을
낮춘 결과를 기본 추출에 승격하려면 비등고선/인접 선 간 이동과 독립 구역 검증이 필요하다.

## 재추적 경로의 교차·인접 선 검사

`short-ink-recovery-v3`는 기존 지지 판정을 바꾸지 않고 선분 전체 교차와 다른
원선과의0.75픽셀 미만 근접, 후보끼리의 교차를 별도 위상 검사로 추가한다.
부모 원선의 단일 끝점 접촉만 허용하며 되짚는 중복 구간은 제외한다.
입력 후보를 변경하지 않고 별도 사본에 검사 결과를 붙인다.

낮은 기준의11개 경로 중10개(관측 지지8개+비지지 일부 포함2개)가 이 기하 검사를
통과했다. R009-weak-020은 observed-004183과 교차/중복되어 보류됐다.
추가 원선 조사에서 이3.414픽셀 원선은(727,237)→(728,238)→(728,239)→(728,240)
이고 새 재추적 경로와 일부 겹친다. 따라서 이를 의미적 오연결로 확정하지 않는다.
기존 중간 조각을 건너뛰고 통째로 잇는 대신, 원선 조각을 보존하면서 새 잉크 구간만
추가하는 다중 조각 연결/출처 추적이 다음 요구사항이다.

비-QGIS493개 시험이 통과했다. 실제 원선 또는 전역 망은 아직 수정하지 않았다.

## 재추적 중복 구간과 새 구간의 분리

`recovery_edge_partition.py`는 정수 픽셀 인접 간선을 무방향 키로 비교하여 기존
관측 간선과 새 복원 간선을 분리한다. 기존 간선에는 원래 경로ID와 간선 인덱스를
남기고 원본 도형을 수정하지 않는다. 경로를 반대 방향으로 따라가도 기존 간선을
새 잉크로 세지 않는다. 평활화된 좌표를 정수에 강제로 붙여 소유권을 만들지 않도록
원래 좌표계 왕복 수준의1e-5픽셀 오차만 허용한다.

`short-ink-recovery-v4`의 R009-weak-020은 새 간선9개와 기존 간선2개로 분리됐다.
기존 구간은(728,240)→(728,239)→(728,238)이다. 위쪽 새 구간을 그대로 합치면
(728,238)의 원래 연결 차수2가3으로 증가한다는 것도 검출했다. 따라서 단순 중복
삭제만으로는 올바른 연결이 되지 않는다. 원선의 실제 끝점(727,237)을 거쳐 중간
조각 전체를 재사용하는 다중 조각 경로를 별도로 검토해야 한다.

기존 교차 보류 기록은 유지했다. 이 분할은 병합 승인이나 등고선 의미 판별이 아니며
원본/승인선/전역 망을 바꾸지 않는다. 비-QGIS497개 시험이 통과했다.

## 중간 원선 조각을 경유하는 복원

`fragment_chain_recovery.py`는 겹치는 중간 원선이 하나인 제한된 사례에서 그 조각의
실제 양 끝점을 사용해 두 짧은 끊김을 재추적한다. 원선 전체는 순서만 맞춰 보존하며
기존 관측 픽셀은 두 재추적 구간에서 제외한다(각 구간 끝점만 허용). 두 구간이
성공해도 교차·재방문·새 분기를 다시 검사하고 자동 병합하지 않는다.

`short-ink-recovery-v6`의 실제 R009 사례는 아래쪽(728,244)→(728,240)의4픽셀
복원만 잉크와 기하 검사를 통과했다. 위쪽(727,237)→(729,233)은 잉크 지지가
부족해 보류됐다. 따라서 중간 조각을 온전히 경유하는 전체 연결은 아직 성립하지
않았으며, 안전하게 확인된 아래쪽 부분만 `supported_subgap_previews`에 보존했다.
완성된 전체 경로를 만들어낸 것처럼 처리하지 않는다.

합성 시험에서는 중간 원선의 완전 재사용·역방향 순서·흰 공백 보류·부분 성공 보존을
확인했다. 원본 지도·승인선·전역 망은 그대로이고, 더 넓은 문맥/잉크 기준 검증과
실제 등고선 판정이 필요하다. 단일 중간 조각 이외의 일반적인 다중 조각 복원은 남아 있다.

## 숫자 후보가 재추적으로 되살아나는 문제의 보호

`recover_short_observed_gaps.py --numeric-separation`은 고정 숫자 분리 보고서의
타일/원본 해시와 압축 배열 해시·크기를 확인한 뒤 최종 병합 숫자 마스크를 사용한다.
보호 잉크와 겹치는 숫자 마스크는 거절한다. 정점뿐 아니라 경로가 통과하는 픽셀 칸
전체를 검사하며, 겹치는 경로는 원래 잉크 지지 판정을 보존한 채
`held_for_numeric_review`로 보류한다. 전체/부분 중간 조각 복원에도 적용한다.

`short-ink-recovery-all24-v3`에서 R004-weak-016이 숫자 후보1픽셀을 통과해
새 보호 검사에서 보류됐다. 이 경로는 기존 기하 검사를 통과했으므로 추가 보호가
실제로 다른 실패 유형을 잡았다. 생성80개 중 기하와 숫자 비중첩 검사를 모두
통과한 것은77개이며 이것도 등고선 의미 승인 수가 아니다. 기존 마스크가 놓친
문자·기호는 이 보호만으로 제거되지 않는다. 구역별 한도 미실행102개도 그대로다.

비-QGIS504개 시험이 통과했다. 입력 원본·승인선·기존 숫자 분리 스냅샷은 보존했고
기본 지도에 재추적 경로를 자동 합치지 않았다. ZIP은 최신 소스로 재생성한다.

비-QGIS509개 시험이 통과했다. 이 프로젝트는 전체 도엽의 최종 등고선 지도가 아니다.

## 소수 구분기호를 포함한 숫자 몸체 후보

숫자 획 소유권의 어휘 게이트가 점/쉼표 구분기호를 가진2–6자리 숫자형 읽기도
받도록 보완했다. 두 배율의 정확한 문자열 일치와 점수 조건은 유지한다.
쉼표를 소수점으로 확정하거나 표고값으로 변환하지 않으며 작은 구분기호 획의
소유권도 따로 확정하지 않는다. 부분 문자열 비교의 자리 수에서 구분기호를 제외하되,
작은 성분 제외는 구분기호 있는 전체 후보에만 적용해 기존 정수 보호를 유지한다.

첫 실제 실행 v4에서 정수0290 후보의 작은 원형 기호 성분 제외가 기존290 분리를
무효화하는 회귀를 발견했다. 적용 범위를 위처럼 제한한 `numeric-separation-all24-v5`
에서는 R001의229픽셀과 기존505/100 분리가 유지됐고 R005의 숫자 몸체114픽셀이
추가 분리됐다. R005의 앞자리와 구분기호 일부는 남아 있다. 24개 개발 구역 결과는
유지42,754개·숫자 후보32개·전체42,786개이며 실제 QGIS에서 모든 저장 도형의
유효성과 원래 좌표의 정확한 일치를 확인했다.

기존 QGIS 검수 프로젝트는 앞선 숫자 분리 v3를 고정 참조하므로 이 새 v5 결과가
그 프로젝트에 자동 반영됐다고 해석하면 안 된다. 자동 학습/승인/표고 할당은 없고
소수점 전체 인식이나 전역 숫자 제거를 완수한 것도 아니다.

## 최신 숫자 분리의 하위 단계 전파와 승인 출처 보존

숫자 분리v5를 입력으로 `short-ink-recovery-all24-v5`와 `numeric-gap-context-v6`를
다시 생성했다. 짧은 복원504개 후보의 검사는 유지됐고 기하/숫자 통과80개,
R004-weak-016 숫자 중첩 보류도 같았다. 새 숫자 문맥으로 R005가 곡선 후보 검사에
추가됐지만 자동 연결이나 승인은 만들지 않았다.

프로젝트 빌더는 사람 승인 기록이 현재 재실행 보고서와 달라도, 원래 승인 시점의
보고서·명시적 판단 파일·도형·원본 지도 해시가 일치할 때만 별도 승인 레이어로
유지할 수 있게 했다. 원래 판단에서 다시 계산한 국소 수정본과 저장 도형/승인
범위가 다르면 거절한다. 재실행으로 기존 승인 출처를 새 후보에 옮기지 않는다.

`qgis-review-v4`를 실제 QGIS3.44.8에서 저장 후 다시 열어16개 레이어·24개 북마크,
1,168,548개 정점의 정확한 좌표 일치와 도형 유효성·읽기 전용·상대 경로를 확인했다.
숫자 후보32개, 짧은 복원80개, 이전 곡선13개, 기존 승인23개와 국소 직선1개는
각각 별도다. 비-QGIS515개 시험이 통과했다. F001/F002는 미승인으로 유지한다.

## 별도 연속 벡터 후보 조립

`assemble_reconstruction_network.py`는 검증된 프로젝트 사본의 숫자 분리 후 원선과
새 복원 간선, 국소 직선 승인을 입력으로 기존 차수2 끝점 병합기를 사용한다.
검수 사본/원본 해시와 재생성된 복원 내보내기의 일치를 확인하고, 양 끝점이 원선
끝점과1e-5픽셀 이내에서 맞는 추가 구간만 조립한다. 이는 좌표 왕복 오차 범위이며
실제 간극을 스냅해서 없애지 않는다. 기존 승인23개는 임의로 다시 붙이지 않고
원래 파일 그대로 별도 보존한다.

`assembled-network-v1`은 원선42,754조각에 복원80개와 국소 승인 직선1개를
사용해 연속 후보38,852개를 생성했다. 원선만의 병합에 비해 열린 끝점이
65,612→65,450으로 줄었다. 원선의 기존 차수2 병합도 포함되므로 단순 입력/
출력 선 개수 차이를 새 복원의 효과나 정확도로 해석하면 안 된다.
전체 조각이 정확히 한 번씩 사용되고, 출처 목록으로 재조립한 모든 정점이 결과와
일치함을 확인했다. 전체 선의 사람 승인/등고선 의미는 false로 남긴다.

실제 QGIS에서38,852개 도형의 유효성과 저장 좌표 일치를 확인했다. 끝점 병합/
복원 내보내기/승인 출처 관련16개 시험도 통과했다. 원래 지도나 기존 검수 프로젝트는
수정하지 않았고, 새 파일은 아직 의미 검수 전 연속 후보 시나리오다.

## 조립 후 원본 근거 평활화

`smooth_assembled_reconstruction.py`는 복원/승인 연결이 포함된 연속 선만 대상으로
기존 원본 법선 프로파일 평활화기를 적용한다. 구성 조각 출처로 원래 정점을 다시
재구성해 일치 여부를 확인하며 승인 연결과 비지지 추론 구간의 원래 인덱스 범위는
고정한다. 지정 개발 구역 밖 구간도 기존 정책대로 고정하고, 전체 회전량이 늘면
보정을 채택하지 않는다. 고정 구간의 저장 좌표는 원래 값으로 정확히 재사용한다.

`smoothed-network-v1`은 연결 포함 선78개 중64개에 보정 초안을 채택했다.
실제 QGIS에서 전체38,852개 도형의 유효성을 확인했고, 보정 전후 공간 인덱스로
모든 변화 선을 조사해 새 자기 교차0개·새 선간 교차 쌍0개임을 확인했다.
이는 현 사본에 대한 검사이며 평활화기의 보편적 위상 보장을 의미하지 않는다.
가장 큰 이동 사례는1.362픽셀로, 원래 총 회전450도에서90.892도로 줄었다.
해당 선이 등고선인지 여부는 여전히 별도의 의미 판정 대상이다.

승인/추론 구간 고정과 출처 불일치 거절 시험을 포함해 비-QGIS517개 시험이 통과했다.
원본·기존 승인·이전 조립 결과·F001/F002 검수 카드는 변경하지 않았다.

## 명시적 비등고선 판단의 새 선망 대조

기존 사람 전용 학습 준비 스냅샷은 전체 선 의미 학습 라벨 양성0·음성0으로 확인됐다.
연결 승인을 전체 선 의미 라벨로 전환하지 않고, 기존 명시적 국소 비등고선 판단을
새 연속선에 대조하는 `semantic_reference_overlap.py`와 검수 내보내기 스크립트를
추가했다. 0.5픽셀 이하 간격으로 방향이30도 이내이고 거리1픽셀 이내인 겹침을
측정하되, 전체 선에 의미를 부여하지 않는다. 수직으로 가로지르는 선은 근접만으로
같은 의미 참조로 판단하지 않는다.

`semantic-overlap-review-v1`에서 A0137 명시적 비등고선 참조와 C009908의
약20.414픽셀 구간이 일치해 의미 검수 우선 레이어로 분리됐다. 국소 참조/겹침의
출처를 보존했고 형상은 바꾸지 않았다. 잘 연결된 비등고선을 오연결 학습 사례로
잘못 사용하는 것도 방지한다. 이 대조는 분류 모델 학습이나 전체 선 분류 완료가 아니다.

## 관측·조립·평활화·의미 검수의 통합 비교

`build_integrated_network_review.py`와 `integrated-review-v1/contour-network-review.qgz`로
단계별 결과를 한 프로젝트에 묶었다. 관측선/조립선/평활화선은 상호 배타적인 비교
그룹으로 전환하고, 국소 비등고선 참조 겹침은 별도 기본 숨김 레이어로 유지한다.
앞 단계 입력 해시를 확인해 서로 다른 실행 결과를 무심코 섞지 않도록 했다.

실제 QGIS 저장 후 재열기에서20개 레이어·24개 북마크, 추가 비교 레이어의
1,745,576개 정점 좌표 일치와 도형 유효성, 읽기 전용·폴더 내부 상대 경로를
확인했다. 한 비교 단계만 기본 선택되는 것도 재검사했다. 최대 이동 사례 C012818의
원본/조립/평활화 그림을 실제 QGIS로 렌더링하여 픽셀 계단이 줄어든 형태를 점검했다.
이는 선택된 형태 비교 예시이고 등고선 의미 정확도 평가가 아니다.

기존 검수 프로젝트와 승인 기록은 보존됐으며 F001/F002는 여전히 미승인이다.

## 평활화 위상 검증의 자동 실행 관문

`validate_network_topology.py`로 수동 조사였던 QGIS/GEOS 비교를 재현 가능한
검증 명령으로 만들었다. 선ID/타일/CRS가 달라지면 거절하고, 새 무효 도형·끝점 이동·
자기 교차·선간 교차를 보고한다. 기존에 있던 교차를 새 실패로 잘못 세지 않는다.
실패 보고서도 남기되 명령은 실패 종료하며 입력 도형은 수정하지 않는다.

`network-topology-validation-v1`에서38,852개 선 중 변화64개가 검증을 통과했다.
통합 프로젝트 빌더는 이제 이 검증 보고서와 평활화 전후 파일 해시의 정확한 일치를
필수로 확인한다. 누락/실패/오래된 다른 도형의 검증 보고서로는 프로젝트를 생성하지 않는다.
`integrated-review-v2/contour-network-review.qgz`는 이 관문을 통과하고 저장·재열기 및
기존 좌표 검사를 다시 완료한 패킷이다.

새 선간 교차·기존 교차·끝점 이동·새 자기 교차의 회귀시험을 포함해 로컬 QGIS
통합19개 시험이 통과했다. 전체 의미 분류·독립 지도 정확도는 여전히 별도 요구사항이다.

## 기존 교차 선 쌍 내부의 추가 접촉 검증

교차 선 쌍 집합만 비교하면 이미 교차하던 같은 두 선 사이의 추가 교차나 접촉
위치 이동을 놓친다는 한계를 보완했다. 기존 교차 쌍도 GEOS 교차 도형을 구한 뒤
이전 접촉에 포함되지 않는 새 접촉 부분이 있으면 실패로 처리한다. 프로젝트
빌더는 이 추가 검사가 수행됐다는 표시도 요구한다.

`network-topology-validation-v2`에서 기존38,852개 선과 보정64개를 다시 검사했고
새/이동 접촉이 없어 통과했다. 기하 파일은 바꾸지 않았으므로 대형 QGIS 프로젝트를
중복 생성하지 않았다. 같은 쌍의 추가 교차·접촉 이동 회귀시험을 추가해 로컬 QGIS
통합21개 시험이 통과했다. 이전v1 보고서는 당시의 더 좁은 검사 기록으로 보존한다.

## 기존 OCR 근거부터의 통합 실행 명령

`run_reconstruction_pipeline.py`가10개 단계를 명시적 argv로 실행한다. 종료 코드와
필수 산출물을 확인하고 실패 뒤 후속 단계를 실행하지 않는다. 단계별 기록은 각각
새 파일로 보존하고 최종 상태는 마지막에 한 번 쓴다. QGIS macOS 실행기 링크는
실제 경로로 풀지 않아야 동작한다는 문제도 실제 실행에서 확인해 수정했다.

`pipeline-run-v3`에서 원본 관측선 재추출부터 최종 QGIS 저장까지10단계를 약109초에
통과했다. 최종20개 레이어·24개 북마크와 연속/평활화 후보38,852개가 재현됐다.
입력 및 구현 해시가 실행 내내 동일했는지도 확인했다. 기존v1은 상태 파일 재생성,
v2는 QGIS 실행기 링크 처리 문제로 중단된 스냅샷이며 성공 실행으로 취급하지 않는다.

실행법과 필요한 기존 자료는 `docs/run-contour-reconstruction.md`에 있다. 이 명령은
기존 고정 OCR 근거를 소비하며 새 모델 다운로드나 학습·승인·git push를 하지 않는다.
`completed_review_pipeline`은 실행 완료일 뿐 전체 등고선 품질 검증 완료가 아니다.
실패 중단·누락 산출물·단계별 기록·실행기 링크 보존 시험을 포함해 비-QGIS525개가
통과했다. 의미 분류/사람 검수/독립 지도 평가는 여전히 남아 있다.
