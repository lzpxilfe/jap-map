## 사용한 기능과 추가 제한

- 정확한 upstream Python 파일 41개의 SHA-256을 확인한 뒤 별도 사본에서 실행했습니다.
  고정 목록은 `examples/contour_assisted_upstream.v1.json`입니다.
- 기존 모델이 유지한 길이 24픽셀 이상 선의 자유 끝점을 사용합니다. 거절된 이웃 선도
  분기 차수에 포함해, 이웃을 지운 탓에 생긴 가짜 자유 끝점을 쓰지 않습니다.
- 12픽셀 뒤의 접선과 양끝 정렬 30° 이내, 거리 3–96픽셀, 끝점당 최대 두 대안을 시험했습니다.
- upstream 320픽셀 Live-Wire, 100% assist, 5점 smoothing과 조건부 Recovery를 그대로 썼습니다.
  이미 있는 검증된 EfficientSAM ONNX cache를 읽었고 모델 다운로드·QGIS 설치는 하지 않았습니다.
- 모든 공백 후보에 최신 connected-outward sampler를 요구했습니다. **upstream의 사람이
  확인한 양끝점 계약을 기계가 충족했다는 뜻은 아닙니다.** 자동 endpoint 선택은 별도 휴리스틱입니다.
- 첫 육안 검토에서 긴 연결이 다른 등고선을 넘는 실패를 확인했습니다. 이후 제3의 기존 선에
  닿거나 가로지르는 후보를 제외하고, 자동 추론 공백을 16픽셀로 제한했습니다.
  끝점 대안이 경쟁하면 잉크 지지·짧은 경로 순의 초안 하나만 유지했습니다.

이 기하 선별은 같은 개발 결과를 보고 추가한 **사후 개선**입니다. 새 독립 평가로 표현하지 않습니다.
선택한 18개를 AI가 직접 보아 도로·기호·혼합으로 판단한 9개를 더 제외했습니다.
`examples/contour_assisted_visual_review.ai-v1.json`에 판독·이유를 별도로 기록했습니다.
AI 판독도 틀릴 수 있고 사람 승인이나 학습 정답이 아닙니다.

기존 유지 선과 다른 AI 제안과의 새 충돌이 없음을 확인했고, 수정선을 원본 CRS의 별도
GeoJSON으로 저장했습니다. 사용자 요청은 `chat-007/refinement-request.json`, 당시 도형·비교판은
`chat-007/refinement-A0013/revision-r1/`에 있습니다. 원래 444개 도형과 기본 추론기는 바꾸지 않았습니다.
후속 구현은 중간 GeoJSON의 CRS 선언을 보강하고, 사람 승인을 자동 선별 입력으로 사용할 수 없도록 했습니다.
앞으로의 별도 곡률 수정에는 방향을 명시한 `--subtle-side`로 작은 초기 변위를 선택할 수 있습니다.

사용자는 **숫자를 넣기 위해 주변 선을 넓게 생략하는 인쇄 관행**을 설명했습니다.
따라서 숫자 주변의 흰 공간은 실제 선이 없는 배경의 증거가 아니며, 여러 등고선이 함께
끊길 수 있습니다. 앞으로의 검수에서는 더 넓은 영역에서 곡선의 진행 방향·곡률·인접 순서를
비교하고, 연결 상대가 애매하면 별도 가설로 질문합니다. 이 설명은 해당 지도에 대한 사용자
지식으로 보존하며 모든 지도·모든 빈칸의 확정 라벨로 일반화하지 않습니다.

기존 16픽셀 제한은 자동 초안의 위험을 줄인 선별 조건일 뿐, 숫자 주변 생략 길이의 상한이나
올바른 연결의 증거가 아닙니다. 이번에는 이 **검수 지침을 기록**했으며 기존 생성·선별
알고리즘, 분류기, 학습·평가 데이터는 변경하지 않았습니다. 표시된 제안에 대한 판단을
그 끝점이 속한 전체 원본 선으로 전파하지 않습니다.

곡률 수정안은 사용자 요청 기록에 묶어 원본 패킷 밖의 새 폴더에 재생성할 수 있습니다.

원래 8,105개 도형과 새 444개 픽셀→지도 좌표를 다시 대조했습니다. Pillow와 실제 추론에

분류기 구현 해시도 그대로입니다. 공주 홀드아웃은 사용하지 않았습니다.
새 QGIS는 13개 레이어와 444개 북마크를 가지며, 상대 경로와 원본 CRS를 명시합니다.
초기 QGIS 초안의 GeoJSON CRS 해석 차이는 최종 프로젝트에서 바로잡았습니다.

비-QGIS 회귀 177개, QGIS 3.44.8 통합 9개, upstream의 공백·Recovery·adapter 관련
선택 테스트 55개를 확인했습니다. 원본/제안 비교와 QGIS 렌더도 확인했습니다.
추론 실행 환경은 Python 3.12.14, NumPy 2.5.1, SciPy 1.18.0, Pillow 12.3.0,
ONNX Runtime 1.28.0, OpenCV 5.0.0입니다. OpenCV는 upstream 문서의 선언 범위
4.8–4.11 밖이므로 이 실행을 공식 지원 조합의 검증으로 간주하지 않습니다.
테스트용 pytest만 임시 폴더에 준비했고 기존 런타임·QGIS 환경은 변경하지 않았습니다.

최초 `configuration.json`의 `no_fitting_or_E_labels_read`라는 키 이름은 부정확했습니다.
기존 평가 보고서를 index로 읽으므로 그 파일의 E 라벨 필드도 JSON으로 로드됩니다.
정확한 의미는 **E 라벨 필드를 학습·선택 계산에 사용하지 않음**입니다.
새 생성 코드는 `no_fitting_or_E_label_use`로 고쳤고 원래 실행 기록은 변조하지 않았습니다.
어느 단계도 새 정확도 평가나 E 라벨을 사용한 재학습을 수행하지 않습니다.

재실행에는 고정 upstream checkout, 이전 개발 입력과 별도 Python 환경이 필요합니다.
모든 출력은 새 폴더여야 합니다. 실행 순서는 아래와 같습니다.

```sh
python scripts/generate_assisted_contour_drawing.py \
  --upstream /path/to/pinned-upstream \
  --model-cache /path/to/existing-verified-cache \
  --output data/derived/assisted-next/raw
python scripts/screen_assisted_contour_drawing.py \
  data/derived/assisted-next/raw/drawing-report.json \
  --output data/derived/assisted-next/screened
```

AI 육안 판독 파일은 정확한 source report 해시에 묶입니다. 다른 실행에 무조건 이전하지 마세요.
QGIS builder에는 최종 판독을 적용한 report와 새 `--output`을 지정합니다.
